# Source scan, 25 September 2026

Out of cycle, prompted by computepulse.net/hopper. There's no new candidate. Six rows
were added, all watchlist. The useful find is the feed behind that page:
Shadeform's instance catalog answers without a key and puts a country on nearly every row.

## The Hopper page itself

ComputePulse has already been screened (2026-09-12 scan, row `computepulse`) and nothing
about that verdict changes. On 25 September the page says indices are computed "only from live API sources" and
names them: "Azure, RunPod, Vast.ai, and Shadeform-aggregated providers". That list now has
RunPod on it, which the methodology page did not on the 12th. Three of those four feed
this project first-hand. The static rate cards it shows but excludes (AWS, GCP, Oracle,
CoreWeave, Lambda) are all already on the register.

So Shadeform is the only input of theirs this register had never screened, and it was
the one worth opening.

## Shadeform

`GET https://api.shadeform.ai/v1/instances/types` returned 299 instance types from 19
clouds on 25 September with no key sent, even though the API reference documents an
`X-API-KEY` header. Every row has `cloud`, `num_gpus`, `hourly_price` in cents, and an
availability list whose `display_name` starts with a country code: "FI, Helsinki",
"NL, Amsterdam", "IS, Blonduos 2". 306 of the 308 H100/H200/B200/B300/A100
availability rows are `on_demand`.

On gate 3 that is better than most operators manage for themselves. It fails gate 5
anyway, and the evidence is in the database rather than in Shadeform's marketing. Shadeform
rows compared with this project's own observations for 2026-09-24:

| Operator, SKU | Shadeform | First-hand | Source of first-hand |
|---|---|---|---|
| Lambda H100 SXM x8 | $3.99 | $3.99 | lambda_pricing, gpuhunt |
| Lambda B200 x2 | $6.89 | $6.89 | lambda_pricing, gpuhunt |
| DigitalOcean H100 x8, NL | $4.41 | $4.41 | digitalocean |
| Scaleway H100 SXM x2, FR | $3.30 | $3.31 | scaleway (EUR converted) |
| Nebius H200 x8, FI/FR | $4.52 | $3.48 | gpuhunt |
| Verda H200 x8, FI | $4.21 | $3.36 | gpuhunt |

All per GPU-hour. Four operators pass through to the cent, and two come back 25-30%
higher. The row itself doesn't say which case it is. I can't tell from here whether
that gap is Shadeform's margin or staleness in gpuhunt's Nebius and Verda catalogs. The
`static_yaml` Nebius H100 x8 entry sits at $3.85, next to Shadeform's $3.87 and a long
way from gpuhunt's $3.00, so the gap may be in gpuhunt rather than in Shadeform. Either
way, "the same price as going direct" doesn't hold for every row, and an index can't
use an aggregator that is right only some of the time.

Gate 4 is unread as well: `shadeform.com/robots.txt` reset the connection twice, and
`/terms` 404s on both domains.

Recorded `watchlist`, used as a channel. It is the most complete location source found
so far for operators that print no country of their own.

Query for the table's first-hand column:

```sql
SELECT provider, source, gpu_model, gpu_count,
       ROUND(AVG(price_usd_per_gpu_hr), 4), GROUP_CONCAT(DISTINCT country)
FROM observations
WHERE ts_utc >= '2026-09-23'
  AND provider IN ('lambdalabs','digitalocean','scaleway','nebius','verda')
GROUP BY 1, 2, 3, 4;
```

## What the catalog named

Five clouds in it had no row here.

**Horizon Compute** is the one that matters. It lists 8-GPU on-demand H100 nodes at
$1.95/GPU-hr and H200 at $3.00/GPU-hr in Blonduos, Iceland. Iceland is in
`eu_eea_countries`. Horizon says it owns its clusters outright, so this is an operator
rather than a reseller. The operator's own site says it prices "$ / GPU-hour" but prints no
number and routes to a contact page. Gate 1 fails for the first-hand route, and gate 5
fails for the only route that has a price. Nscale's Blonduos site (2026-09-12 scan) is in
the same town.

**Excess Supply** has H200 in Helsinki and Paris at $4.63 (x1) and $4.52 (x8), which are
the same numbers as Shadeform's Nebius rows in the same two cities. No homepage turned
up. It looks like resold Nebius capacity, and if it is, admitting it would count one
operator twice.

**Boost Run** is H200 and B200 x8 in Dallas and Raleigh. The ComputePulse page shows these
rows with region "none", although Shadeform has the cities. Its own site: "Pricing is
custom and scoped to your configuration and term length."

**IMWT** (H100 x1-8, Des Moines) and **Amaya** (H200 x8, Dowagiac, Michigan) are US-only and
have no operator pricing page that I could find. Phyntec is also in the catalog, with
consumer cards only, so it gets no row.

The catalog also lists Vultr A100 80GB in Frankfurt, which Vultr's own `/v2/plans` did
not show on the 12th. It is 1-GPU only, so gate 2 would still fail, and the `vultr` row
is unchanged.
